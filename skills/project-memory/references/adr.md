# ADR

ADR 记录仍然有效的长期决定和理由，格式见项目的 `decisions/ADR-0001-template.md`。

## 什么时候写

- 选择或更换主要技术栈、架构边界、数据模型、接口格式或重要依赖。
- 以后的开发者需要知道“为什么现在是这样”。
- 要替代一个仍被代码或文档引用的旧决定。

调试过程和单次实现写进 `development/`；还没有结论的讨论写进 `requirements/open-questions.md`；没采用的方案写进相关 ADR 的“替代方案”。

## 状态

- `proposed`：候选，还没批准。
- `accepted`：当前有效。

## 替代旧 ADR

1. 用当前最大编号的下一个号建新 ADR，在“替代关系”里写旧 ADR 的编号、原路径和替代原因。
2. 把旧 ADR 里仍有用的背景、约束和替代方案写进新 ADR。
3. 更新架构文档、`INDEX.md` 和指向旧 ADR 的链接。
4. 删除旧 ADR 文件。

按这个顺序做，新 ADR 先占住编号，删掉旧文件后编号也不会回退。
