# 中文句式清单

配合 `SKILL.md`“要去掉的写法”使用。这里只作排查线索：看到这些词时结合句子意思判断，不要按词一刀切替换。

## 常见句式

| 句式 | 开发文档 | 使用者文档 |
| --- | --- | --- |
| 不代替 / 不等于 / 不构成 / 不能视为 / 不代表 | 表达边界或禁令时留下（如“静态检查不代替集成测试”）；只是防御性免责就删 | 改成明确的结果或操作提示，如“预览效果仅供参考，以实际导出为准” |
| 尚未 / 待 / 未 | 写清当前状态和缺口，同一缺口只写一处 | 有明确安排再写（如“计划在 2.1 支持”）；不确定就只写现状（如“暂不支持”），不编造排期 |
| 不适合 / 不建议 / 不推荐 | 带具体原因或后果的留下；没有原因就删 | 说清适用场景或风险（如“生产环境开启会明显拖慢响应”） |
| 只能 / 仅 / 允许 / 不允许 | 规定权限、真正的技术边界或前置条件时留下；属于工具职责常识（如“检查脚本只读不装”）、显而易见的系统行为或与上文重复时删掉 | 直接说明支持的范围或用法（如“支持 JPG、PNG 和 WebP”） |
| 会直接报错 / 无法…… / 会失败 | 仅当报错行为反直觉、或需要指出特殊排查方式时留下；属于常识性后果（如“JSON 写错会报错”“断网无法下载”）直接删掉 | 写清报错后用户该怎么处理 |
| 不是 A，而是 B / 并非 A，而是 B | 直接写 B；需要对比旧方案时补一句“以前是 A” | 直接写 B |
| 基本可用 / 基本完成 / 初步支持 | 写清哪些已实现、哪些还没做 | 同左 |
| 需要注意的是 / 值得一提的是 / 顺便说明 | 删掉开头套话，直接写后面的内容 | 同左 |
| 综上所述 / 总而言之 / 以下是几点说明 | 删掉 | 删掉 |
| 进行 + 动词（进行扫描、进行校验） | 直接用动词（扫描、校验） | 同左 |
| 充分保障 / 有效提升 / 显著增强 | 有实测数据就写数据，没有就删 | 同左 |
| 不仅是 A，更是 B / 标志着 / 彰显了 | 删掉评价，只留事实 | 同左 |
| 新增 / 接入 / 引入 / 落地 | 现状文档写当前支持什么（如“支持 CSV 导出”）；变更日志里可以用 | 写现在能用它做什么 |
| 在某些情况下可能 / 存在一定关联 | 有证据就直接写结论；没有就留一处“可能”，写明缺什么证据 | 同左 |

## 警惕词

这些词常被用来掩盖没说清的逻辑：契约、范式、矩阵、闭环、链路、维度、颗粒度、口径、抓手、底座、赋能、对齐、拉通、沉淀、兜底、配方、校注、落地、打通、水位。

看到时优先换成平实、准确的书面表达。项目术语表定义过的词、字段名（如 `id_high_water`）和常见技术术语（如“冒烟测试”）保留。

## 过度口语化

去公文腔的目标是简洁、准确的技术书面语，不是聊天口语或电报体碎句。

| 常见口语写法 | 建议写法 |
| --- | --- |
| 表头与枚举：要不要 / 填什么 / 要·不用 / 情况 | 是否需要 / 说明·字段 / 是·否 / 场景 |
| 动词与虚词：改 / 装 / 跑 / 配好 / 记在…里 / 报…错 / 把…填进去 | 修改 / 安装 / 运行·执行 / 配置完成后 / 记录在…中 / 提示… / 填入 |
| 强行口语化的技术称呼：电脑端 / 移动端网页 / 文档提供者 / 原文 | 桌面端 / 移动端前端页面 / `DocumentProvider` / 文件内容 |
| 用户文档里的开发术语或随意口语：失败可回滚 / 扫它 / 填 | 出错可恢复 / 扫描 / 填入 |

## 标点和排版

- 中文正文用全角标点和全角引号“”。代码、命令、JSON 和英文专有名词里保持原样。
- 中英文、中文和数字之间是否加空格，跟随项目现有文档。
- 粗体只用来标出关键词，不整句加粗。

## 示例

**开发文档，改前（公文套话与绕弯否定）：**

> 本次重构充分提升了导入模块的健壮性。需要注意的是，目前尚未对超过 1 GB 的文件进行导入验证，因此不能认为该场景已经通过，也并不意味着该场景一定存在问题。

**改后：**

> 还没测过导入超过 1 GB 的文件。

---

**开发文档，改前（工具自证、常识废话与含糊简称）：**

> `pnpm doctor` 检查 Node、pnpm、JDK 和 Android SDK 是否齐全，只读取环境，缺少的工具要自己安装。只开发电脑端时用 `pnpm doctor --desktop`，不检查 Android 工具。`pnpm dev:mobile` 在浏览器里打开移动端网页，适合调界面；目录、传输等原生功能只在 Android 应用里可用。JSON 写错时命令直接报错。

**改后：**

> `pnpm doctor` 检查 Node、pnpm、JDK 和 Android SDK 是否齐全；`--desktop` 参数指定只检查桌面端开发环境。`pnpm dev:mobile` 在浏览器中打开移动端前端页面，适合调试界面；依赖 Android 原生插件的文件权限与局域网传输功能需在真机或模拟器中调试。

---

**开发文档，改前（过度口语化与碎片化）：**

> 给要在本仓库里改代码、构建或发布的开发者。都在仓库根目录运行。
>
> | 情况 | 要不要配密钥 | 填什么 |
> | --- | --- | --- |
> | 自己开发 | 不用 | 留空 |
> | 发 release 包 | 要 | 密钥路径和密码 |
>
> **只读检查发现文件的 ctime 变了。** 有的文档提供者在首次授权读取后会改 ctime。判断内容是否一致时看原文、大小和 mtime。

**改后：**

> 本文档面向参与本项目开发、构建与发布的开发者。以下命令均在仓库根目录执行。
>
> | 场景 | 是否需要配置密钥 | 说明 |
> | --- | --- | --- |
> | 本地日常开发 | 否 | 默认使用本机调试密钥 |
> | 构建 release 包 | 是 | 提供密钥路径和密码 |
>
> **Android SAF 读取文件后 `ctime` 发生变化**
> 部分系统的 DocumentProvider 在首次授权读取后会更新文件 `ctime`，校验文件一致性时应以文件内容、大小和 `mtime` 为准。

---

**开发文档，不用改：**

> 修改同步协议的字段前，先由维护者确认两端的兼容方案；兼容方案确定前不改字段名。

这一句规定了审批卡点和约束边界，保留。

---

**开发文档，改前：**

> 经确认，导出默认使用 UTF-8，这不仅是一次默认值调整，更体现了对跨平台兼容的重视。

**改后：**

> 导出默认使用 UTF-8。

---

**使用者文档，改前：**

> 本工具仅对图片进行本地压缩，不会上传任何数据；目前仅支持 JPG、PNG、WebP 格式；压缩会造成一定的画质损失，不能保证与原图质量一致。

**改后：**

> 压缩在本地完成，支持 JPG、PNG 和 WebP 格式。
