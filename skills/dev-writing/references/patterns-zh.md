# 中文句式清单

配合 `SKILL.md`“要去掉的写法”使用。清单是检查线索：命中后按句子的作用判断，不按词批量替换。

## 常见句式

| 句式 | 开发文档 | 使用者文档 |
| --- | --- | --- |
| 不代替 / 不等于 / 不构成 / 不能视为 / 不代表 | 表达门禁或边界时留下；只是自证清白就删 | 改成读者要做的动作，如“语法检查过了，还要实际跑一遍” |
| 尚未 / 待 / 未 | 真实的状态和缺口留下；同一缺口只写一次 | 改成短句：“还没做”“下个版本加” |
| 不适合 / 不建议 / 不推荐 | 带原因的决策留下；没有原因就删 | 改成“什么时候用” |
| 只能 / 仅 / 允许 / 不允许 | 规定行为或范围时留下；重复上文就删 | 改成读者要做什么 |
| 不是 A，而是 B / 并非 A，而是 B | 直接写 B | 直接写 B |
| 基本可用 / 基本完成 / 初步支持 | 写清哪些能用、哪些没做 | 同左 |
| 需要注意的是 / 值得一提的是 / 顺便说明 | 删掉外壳，内容留下 | 同左 |
| 综上所述 / 总而言之 / 以下是几点说明 | 删掉 | 删掉 |
| 进行 + 动词（进行扫描、进行校验） | 直接用动词 | 同左 |
| 充分保障 / 有效提升 / 显著增强 | 有数据写数据，没有就删 | 同左 |
| 不仅是 A，更是 B / 标志着 / 彰显了 | 删掉，留事实 | 删掉，留事实 |
| 新增 / 接入 / 引入 / 落地 | 当前态文档写现状；变更说明里可以用 | 写使用者能做什么 |
| 在某些情况下可能 / 存在一定关联 | 有证据写结论；没有就留一处“可能” | 同左 |

## 警惕词

这些词常被用来包装没说清的意思：契约、范式、矩阵、闭环、链路、维度、颗粒度、口径、抓手、底座、赋能、对齐、拉通、沉淀、兜底、配方、校注、落地、打通、水位。

命中后先问有没有更直白的说法。项目术语表定义过的词、字段名（如 `id_high_water`）和通用技术说法（如“冒烟测试”）不算。

## 标点和排版

- 中文正文用全角标点和全角引号“”。代码、命令、JSON 和英文专有名词里保持原样。
- 中英文、中文和数字之间是否加空格，跟随项目现有文档。
- 粗体只用来标出关键词，不整句加粗。

## 示例

**开发文档，改前：**

> 本次重构充分提升了导入模块的健壮性。需要注意的是，目前尚未对超过 1 GB 的文件进行导入验证，因此不能认为该场景已经通过，也并不意味着该场景一定存在问题。

**改后：**

> 超过 1 GB 的文件还没测过导入。

---

**开发文档，不用改：**

> 修改同步协议的字段前，先由维护者确认两端的兼容方案；兼容方案确定前不改字段名。

这段的两个限制都是门禁，保留。

---

**开发文档，改前：**

> 经确认，导出默认使用 UTF-8，这不仅是一次默认值调整，更体现了对跨平台兼容的重视。

**改后：**

> 导出默认使用 UTF-8，以便在各平台上打开。

---

**使用者文档，改前：**

> 本工具仅对图片进行本地压缩，不会上传任何数据；目前仅支持 JPG、PNG、WebP 格式；压缩会造成一定的画质损失，不能保证与原图质量一致。

**改后：**

> 图片在你的电脑上压缩，不会上传。支持 JPG、PNG 和 WebP。压缩后画质会下降，需要原图时请保留原文件。
